# KeyMultiMap — 键盘按键多重映射工具（AutoHotkey v2）

把任意「触发键」变成一把可多重触发的瑞士军刀：单击 / 双击 / 三连 / 四连 / 五连 / 长按，
每一级都能独立映射为不同动作。未配置的层级**原样放行**，绝不吞键。

- **作者**：SantaChains
- **版本**：v0.0.1
- **仓库**：[SantaChains/keyshadow](https://github.com/SantaChains/keyshadow)

---

## 一、功能特性

- **多级触发**：每个触发键支持 单击、双击、3 连、4 连、5 连，外加**长按**（阈值可调）。
- **五种动作类型**：
  - `无`：该层级放行原始按键（默认，保留按键原本功能）。
  - `透传`：屏蔽该按键，不触发任何响应。
  - `发送按键`：发送 AHK 按键序列（如 `F1`、`^s`、`Volume_Up`）。
  - `发送文本`：输入任意文本。
  - `启动程序`：运行可执行文件或打开 URL。
- **设置中心（GUI）**：五页签 —— 按键映射 / 定时参数 / 常规 / 备份与导入导出 / 关于。
- **托盘菜单**：`映射已启用`、`显示托盘图标`、`开机自动启动` 等开关项**带勾选状态**，
  且与设置窗口**双向同步**。
- **导入 / 导出**：默认「按 id 合并」——同名替换、新增追加、本机独有保留，绝不丢失数据。
- **自动备份**：每次保存前自动生成 `config.json.bak`。
- **开机自启**：通过注册表 / 启动目录实现，托盘可随时开关。
- **暂停热键**：默认 `Ctrl+Alt+K`（`^!k`）全局开关所有映射。
- **零依赖 JSON**：配置以 JSON 存储，解析器为自研字符级递归下降实现，无外部库。

## 三、快速开始

**方式 A — 直接运行脚本（开发 / 调试）**

```
KeyMultiMap.ahk
```

双击即可。首次运行且尚无任何「有效映射」（启用且触发键非空）时，会自动弹出设置窗口。

**方式 B — 编译为独立 exe（分发 / 日常使用）**

见下文「八、打包」。生成的 `KeyMultiMap.exe` 无需安装 AutoHotkey 即可运行。

## 四、使用说明

1. 右键托盘图标 → **设置…**，或在启动时选择「打开设置」。
2. 在「按键映射」页签点击 **新建**，填写：
   - **触发键**：如 `F`、`CapsLock`、`Space`、`a`（建议用不常用的键，避免与正常输入冲突）。
   - **单击 / 双击 / 3 连 / 4 连 / 5 连 / 长按**：分别为每一级选择动作类型与内容。
     - `无`：该层级放行原始按键（默认，保留原功能）。
     - `透传`：该层级屏蔽按键，无任何响应。
     - `发送按键`：填写 AHK 按键名，如 `F1`、`^s`（Ctrl+S）、`Volume_Up`。
     - `发送文本`：填写要输入的任意文本。
     - `启动程序`：填写可执行文件路径或 URL。
3. 点击 **应用更改** 使配置生效（热键会即时重建）。
4. 试试连按触发键：单击做一件事、双击做另一件事、按住做长按动作。

> 配置了「双击」的键，其「单击」会**延迟一个连按窗口期**再触发（用于判定你是否还要继续连按）。
> 窗口越短响应越快，但越容易误判；按需求在「定时参数」中调节。

**暂停 / 恢复**：随时按 `Ctrl+Alt+K` 临时停用或恢复全部映射。

## 五、定时标准（连按窗口 / 长按阈值）

这些参数决定「一次按键」与「一次连按」的边界，参考了主流平台的交互规范：

| 参数 | 默认值 | 范围 | 业界参考 |
| --- | --- | --- | --- |
| 连按窗口（Tap Window） | 300 ms | 50–1000 ms | Android `DOUBLE_TAP_TIMEOUT` ≈ 300ms；Windows 双击 500ms；macOS 350ms |
| 长按阈值（Long Press） | 500 ms | 100–2000 ms | Android / Material Design / iOS 标准 ≈ 500ms |

- **连按窗口**：两次按键之间的最大间隔，超过即判为「新的单击」。
- **长按阈值**：按住多久判定为长按（与「连按」互斥，优先匹配更具体的连按级数）。

> 规则：触发后，若在窗口期内再次按下，则连按级数 +1；若按住超过长按阈值，则触发长按。
> 已显式配置的最高级优先；未配置的层级一律放行原始按键。

## 六、配置说明

配置文件位于：

```
%APPDATA%\KeyMultiMap\config.json
```

结构（节选）：

```json
{
  "app": "KeyMultiMap",
  "version": 1,
  "settings": {
    "trayHidden": true,
    "autostart": false,
    "startEnabled": true,
    "tapWindowMs": 300,
    "longPressMs": 500,
    "pauseHotkey": "^!k",
    "feedbackBeep": false
  },
  "mappings": [
    {
      "id": "...",
      "enabled": true,
      "trigger": "F",
      "actions": {
        "1":    { "type": "key",  "value": "F1" },
        "2":    { "type": "text", "value": "hello" },
        "long": { "type": "run",  "value": "notepad.exe" }
      }
    }
  ]
}
```

动作类型映射（`type` 字段）：

| 界面选项 | type | 行为 |
| --- | --- | --- |
| 无 | `none` | 放行原始按键 |
| 透传 | `block` | 屏蔽按键，无响应 |
| 发送按键 | `key` | 发送按键序列 |
| 发送文本 | `text` | 输入文本 |
| 启动程序 | `run` | 运行程序 / 打开 URL |

- 层级键为 `"1"`–`"5"`（对应单击到 5 连）与 `"long"`（长按）。
- 层级**无需连续配置**：例如只配置 `"1"` 与 `"3"` 时，双击放行原始按键，3 连正常触发。
- 每次保存前会自动生成 `config.json.bak` 作为回滚点。
- 直接编辑 JSON 后，可通过托盘菜单 **重载配置** 生效。
- 动作值为空或选择「无」时，该层级放行原始按键。

## 八、打包（编译为 exe）

项目根目录已提供 **`build.cmd`**，一键编译为 `KeyMultiMap.exe` 并嵌入 `logo.ico`：

```
build.cmd
```

脚本会自动定位 AutoHotkey 安装目录下的 `Ahk2Exe.exe` 与 v2 运行时基础文件
（如 `AutoHotkey\v2\AutoHotkey64.exe`），无需手动指定。

> **排错提示**：本机若使用较旧 / 不匹配的 `Ahk2Exe.exe`，编译 v2 脚本可能失败（常见返回码 52）。
> `build.cmd` 已通过 `/base` 显式指定 v2 运行时基础文件来解决此问题；若仍失败，
> 请确保安装的是 **AutoHotkey v2.x 完整版**，且 `Compiler\Ahk2Exe.exe` 与 v2 运行时版本一致。

图标来源为 `logo.svg`（玻璃拟态键盘风格）。如需更换，可先用
Inkscape / ImageMagick 将其转为多尺寸 `.ico`：

```bash
inkscape logo.svg --export-type=png --export-filename=logo256.png -w 256 -h 256
magick logo256.png -define icon:auto-resize=256,128,64,48,32,16 logo.ico
```

## 九、自检测试

脚本内置 JSON 解析 → 序列化 → 再解析的往返一致性自检，可用于验证配置读写是否正确：

```
KeyMultiMap.exe /selftest
# 或直接运行脚本：
KeyMultiMap.ahk /selftest
```

退出码为 `0` 且在 `%APPDATA%\KeyMultiMap\_selftest.log` 中输出 `SELFTEST PASS` 即表示通过；
`reparse : equal` 代表序列化后再解析结果与原文完全一致。

## 十、故障排查

| 现象 | 可能原因 / 解决办法 |
| --- | --- |
| 双击运行后「什么都没发生」 | 首次运行且无有效映射时会自动打开设置；若托盘被隐藏，请先到设置里关闭「隐藏托盘图标」，或任务栏搜索托盘箭头。 |
| 某些按键「吞掉了」 | 检查该触发键是否有层级设为「透传」；「无」会放行原始按键。若不想某键被接管，删除该映射或将其各级设为「无」。 |
| 单击老是延迟才触发 | 该键配置了「双击」等更高级，单击需等待连按窗口结束。可缩短「连按窗口」或移除高级配置。 |
| 改了配置不生效 | 在设置中点击「应用更改」；或在托盘菜单「重载配置」。 |
| 编译失败（返回码 52 等） | `Ahk2Exe.exe` 与 v2 运行时版本不匹配，见第八节 `/base` 说明。 |
| 开机自启不工作 | 以管理员身份运行一次并勾选「开机自动启动」；部分系统需将本程序加入杀软白名单。 |
| 暂停热键无效 | 确认 `Ctrl+Alt+K` 未被其他程序占用；可在设置「常规」页中修改 `pauseHotkey`。 |

## 十二、技术备注（实现要点）

- **JSON 解析器**：自研字符级递归下降解析，不依赖正则，规避 AHK 字符串引号转义问题。
- **位置传递**：解析过程用 `Map("p", 0)` 对象传递游标位置（AHK v2 的 `ByRef`/`VarRef` 在多层转发时存在引用陷阱，对象引用可正确传播）。
- **数字判定**：使用 `Ord()` 取字符码作数值比较，避免 AHK 字符串比较在边界字符上的异常行为。
- **兼容性细节**：AHK v2 中 `FileDelete` 对不存在的文件会抛出异常，故涉及「先删后写」处均包裹 `try/catch`。
- **GUI 写法**：AHK v2 的 `Gui.Add` 仅接受 3 个参数（类型 / 选项 / 文本），事件回调通过 `.OnEvent` 绑定；
  切换页签使用 `Tab.UseTab(n)` 而非 `Tab.Value`，否则控件不会归属到目标页签。
